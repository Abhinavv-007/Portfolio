Use it

curl · fetch · python · command

No keys, no sign-up. The envelope is stable across versions and the data is the same the pages render.

curl 
curl -s https://abhnv.in/api/summary | jq
curl -s https://abhnv.in/api/security | jq '.data.method'
curl -s https://abhnv.in/api/projects/clex-ai | jq
curl -s "https://abhnv.in/api/search?q=authorization" | jq
fetch (browser) 
const res = await fetch("https://abhnv.in/api/projects");
const { ok, data, meta } = await res.json();
if (!ok) throw new Error("API error");
console.log(data.map((p) => `${p.title} — ${p.liveUrl}`), meta.version);
python (requests) 
import requests

base = "https://abhnv.in/api"
areas = requests.get(f"{base}/security").json()["data"]["areas"]
for a in areas:
    print(a["title"], "—", a["short"])
command surface 
// One endpoint, pick the command by name
const cmd = "security"; // summary, projects, research, links, search, help
const url = `https://abhnv.in/api/command?cmd=${cmd}`;
const { ok, data } = await fetch(url).then((r) => r.json());

Why it exists

One data file, two readers

01

Single source

The pages and the API import the same file. A change to a product, a credential or a research area is live in both at once.

02

Read-only

Every route is GET. The only write is the contact form, and it accepts nothing but a message.

03

Edge-cached

Responses are cached for five minutes with stale-while-revalidate, so embeds stay fast and a burst of traffic never reaches a function.

04

What is not here

No deployment metadata, no request geography, no reports, no private programs. The API publishes what the site publishes and nothing more.
